# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 拦污栅清污业务

拦污栅有两份数据：拦污栅台账（`trashrack`）与历史清污记录（`trashrack-history`，localStorage
独立键）。三个页面（拦污栅台账、清污优先序、清污概览）共用同一套清污服务
`frontend/src/api/cleaning-service.ts`，取值规则：

- **压差取实测那一份**：前后压差只来自台账现场实测（含清污完成时录入的清后实测压差），
  历史导入等第二路径不覆盖；两条路径打架时统一到实测值。
- **清污次数唯一口径**：以历史清污记录去重后的条数为准，台账「清污次数」是缓存。
  `reconcileCleaning()` 在进入相关页面、导入记录、确认完成时自动对账，发现不一致就回写台账，
  跨页面清污条数始终相同。
- **自然键去重**：历史记录以「栅体编号+清理日期+清理人」为自然键，重复导入只保留一次。
- **缺项补齐（理由写入备注）**：早期纸质台账只登记清理人、没写清污方式的，按
  2024-01-01 机械清污机投运时点补齐——投运前补「人工清污」，之后补「机械清污」，
  数据来源标「历史台账补录」，补齐理由写进每条备注。
- **清污优先序**：按现场实测压差从大到小排序，压差上限 3.0 m，超限栅体红标单列并显示
  上次清理日期；没有清污记录的栅体保留一行并标注。台账「确认完成」清污后录入清后实测
  压差，次数与优先序立即更新，清完即退出首位。可按机组筛选，另存 CSV 的行数与页面栅体
  台数严格一致。
- **待办同步**：待办清单直接由台账状态（非「已清理/已损坏」）派生，与现场台账永远同步。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`；拦污栅清污的跨页面业务统一走
  `frontend/src/api/cleaning-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在服务层里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries:v2` 这一项，或调用
  `resetModule(模块)`。
